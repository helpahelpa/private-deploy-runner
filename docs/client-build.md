Provision the private, reviewed client packaging snapshot in ignored `local/trusted-tooling/client-build/` before building. `UPSTREAM.json` records the original script hashes and source commit. The game repository's Python scripts, project files, and build hooks are never imported or executed on the host. Update this snapshot through private review when packaging logic changes.

The host entrypoint is:

```sh
python3 scripts/build_client.py --config local/client-build.private.json \
  --source /operator/source --commit <40-character-commit> \
  --output local/releases/<new-release> --version 4.2.0.<allocated-counter>
```

The operator reserves a globally monotonic **incremental asset** counter under the deployment lock; the builder requires a new output directory and a version of at least 62. APK files are published atomically with `manifest.json` and `client-tests.json`. No deployment, ADB, save, preferences, or network write happens here. Assets contain the new incremental pack, update configuration and server list; the deployment layer supplies the retained static asset base.

The Android package version is independent of that asset counter. A private content-addressed store reuses the exact signed APK whenever production Java/C#, relevant trusted packaging/compiler code, pinned native inputs, trust/signing identity and endpoint configuration are unchanged. Source commits, server/docs/test changes and incremental asset version allocations do not cause another APK or native version. Each request produces current incremental assets and an honest QA receipt. The separate whole-client QA cache can reuse successful test evidence only when all admitted source, fixtures, tools, harness and configuration inputs match. This conservative boundary includes shared server inputs visible to client integration tests. There are no per-test caches.

Pass `--force-full-qa`, or select **Force full QA** in the deployment workflow, to rerun every client and server test. This bypasses component test-cache reads while preserving native APK reuse. Forced successful results can populate the component cache for later normal runs. Logs and receipts identify fresh versus reused QA and retain the original tested commit.

The fingerprint schema is also the reviewed contract for material host-wrapper policy. If a future trusted host change alters helper selection, compiler payload injection or package argument defaults, bump the fingerprint schema in `native_apk.fingerprint` (or explicitly invalidate affected cache entries). The vendor packager/compiler files are hashed automatically. Changes confined to QA, diagnostics, logging or documentation must not bump this schema.

`manifest.json` records `apk_input_sha256`, the original `apk_source_commit`, actual `apk_version_code`/`apk_version_name`, and whether the APK was reused. The independent native counter is persisted before signing and failed reservations are never recycled. Retain the private store and counter when moving hosts; deleting them can defeat version continuity. An owner must seed the minimum strictly above all previously installed/published Android version codes when creating a replacement store.

The client assets include `/apk-update.json`, with schema, package, actual Android version code/name, exact APK SHA256/size, signer certificate SHA256 and the same-origin `/client.apk` URL. These fields come from the signed artifact report; they contain no credentials or host paths. Incremental server release versions continue advancing independently.

The private JSON configuration has these fields:

- `apk_cache`: optional absolute private directory for sealed signed APKs and their durable native version counter; defaults to `signed-apk-cache` beside the private build configuration. Keep it outside source/test mounts.
- `component_cache`: optional private directory for the sealed whole-client QA evidence, defaulting to `client-qa-cache` beside this configuration. Keep it outside source/test mounts. Its key covers the entire admitted source snapshot, fixtures, trusted harness, configuration, toolchain bytes and compiled payload. The receipt retains both the original tested commit and the current release commit.
- `qa_workers`: one to four isolated client test containers; defaults to one for existing configurations. This deployment uses four. The reviewed regression harness must support `--shard-index` and `--shard-count`; upgrade the ignored trusted harness before enabling parallel execution. Each QA container has a separate temporary filesystem, a 2 GiB memory limit and two CPUs. Compilation retains its existing separate resource limits. The aggregate must cover the complete discovered suite exactly once and retain every required test ID; a failure or skip in any worker fails the build.
- `minimum_native_version_code`: optional first native Android version allocation (positive Int32). The allocator also exceeds the recovered base APK and every prior reservation. This is separate from the broker's `minimum_version` for incremental assets.
- `image`: an existing immutable Docker image ID, `sha256:…`. The image needs compatible Linux Python, OpenSSL, cryptography, dnfile, dncil and Pillow. The retained AST checks use a provisioned PowerShell toolchain; its parser and pure helper assertions execute inside the same restrictions. Build/test never pulls images or installs packages.
- `toolchains`: read-only `path` and `target` objects. Allowed targets are `/toolchain/jdk`, `/toolchain/dotnet`, `/toolchain/android`, and `/toolchain/pwsh`. Supply dedicated toolchain directories containing no secrets.
- `python_dependencies`: the container path for baked Python packages (defaults to `/python-deps`).
- `toolchain_files`: named `{path, sha256}` pins for the explicit compiler/DEX tools.
- `compile`: container paths `java`, `javac`, `android`, `r8`, `dotnet`, and `csc`. Optional `test_runtime` and `test_tfm` select the provisioned Linux CLR. `minimum_client_tests` and `required_test_ids` retain the reviewed baseline suite.
- `inputs`: named `{path, sha256}` objects for `base_apk`, `client_source`, `template`, `ca`, `key`, `cert`, `helper`, `helper_manifest`, `android_receipt`, `mscorlib.dll`, `System.dll`, `UnityEngine.dll`, and `LitJson.dll`. These are operator-owned, immutable local inputs. The signer must already exist. A matching established managed helper is preserved exactly; changed C# gets a newly compiled helper.
- `apk_download_credentials`: optional packaging-only `{path, sha256}` pin for a mode-0600 JSON file containing only `username` and `password`. Provision the production download account privately outside trusted-tooling and toolchain mounts; never put its value in this repository, command arguments or logs. The credential file enters only the trusted packaging step after every source compilation and test container has exited. Its content hash is a material APK input, so a credential rotation produces a new signed APK while a file relocation does not. The APK deliberately contains this shared download credential; it does not grant a game account or bypass invitation-based registration.
- `connection`: the original builder's endpoint-only configuration (`gameplay_transport`, optional secure `gameplay_url`, and `assets_origin`). Credentials and gameplay proxy settings are rejected; per-install routing remains external to the APK. Omitting the configuration builds the default TLS flavor.
- `fixtures`: relative destination names mapped to pinned private files. They are copied to the isolated source snapshot. `compile.test_fixture_destinations` optionally copies selected relative fixture names into the sandbox's temporary `/mnt/c` for retained test infrastructure.
- `test_commands`: argument arrays, normally `[["python3", "/trusted/regression.py"]]`. Every test container has network disabled, a read-only root and source, no capabilities, no signing identity, and no Docker socket. The trusted harness requires zero skips/errors/failures, retained test IDs, and a real full-suite result. Existing Windows transport fixtures are adapted to compile and execute the exact current C# probes on the provisioned Linux CLR. PowerShell AST checks use real PowerShell with bounded Windows lexical Path operations; packaging scratch uses `/work` while source remains immutable; the receipt identifies this platform explicitly.
- `forbidden_apk_strings`: private values which must be absent from every decompressed APK ZIP entry. Populate this with any actual gameplay proxy hostname/URI, proxy password and access credentials that must never ship. Exclude only the explicitly provisioned APK-download credential intended for the startup updater. Values never enter build output or logs.

Keep that download password and its Basic authorization token in the broker's
private `log_redactions` list even though they are intentionally allowed in the
APK. Reload the broker after changing that private list. Rotating the download
account also requires updating the private credential file's SHA256 pin.

All private configurations, input locations, endpoint values, diagnostics and artifacts belong under ignored `local/`. Only Java and C# production blobs from the exact requested Git commit enter the compiler. Git LFS pointers resolve only to local object bytes matching their committed SHA256 and size, using the checkout’s canonical `.git/lfs/objects` or the operator’s explicit `lfs_object_store`; filters never execute. The receipt hashes all source and fixture data before and after testing. Java annotation processing is disabled; C# is passed directly to the compiler without MSBuild, project evaluation, generators or package restore. Newly compiled application code runs only in the restricted test containers. Signing happens afterward in the trusted host packager.
